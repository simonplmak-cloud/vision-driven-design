Vision Driven Design

Prove your AI-written code did what the business actually asked for.

AI agents now write most of the code. Pick any function in your repository and ask which business goal authorised it. Most teams cannot answer — the prompt is gone, the session is gone, and the commit message says implement user auth.

VDD gives every commit an audit trail back to the business goal it serves, and flags any code that does not have one. What you get is a traceability matrix, a drift report and an impact report — generated, not hand-written.

Why bi-directional

Spec-driven development verifies in one direction: did every specification get implemented? That catches dropped requirements, and it is genuinely useful.

It never asks the opposite question — is there anything here that no specification asked for? Under human authorship that rarely mattered. Agents are different. An agent adds a retry wrapper, then a config layer to make it tunable, then a service to own the config. Each step is locally reasonable. Each passes review. None of it traces to anything anyone requested.

Forward verification catches dropped requirements. Backward verification catches invented ones. VDD runs both at every junction, so drift shows up as a failing gate rather than as a subsystem nobody can justify eighteen months later.

This is not a new idea. Bi-directional traceability is mandatory in aerospace and medical-device software under DO-178C, IEC 62304 and CMMI Requirements Management. It never spread to ordinary software for one reason: maintaining the matrix by hand cost more than the defects it prevented. AI inverts that arithmetic — the agent writing the code can maintain the evidence chain as a by-product of doing the work.

The chain

Every commit traces back through the full chain to the original vision statement:

V-001 → S-002 → T-003 → SP-004 → PL-005 → TK-006 → commit

#PhaseOutput
0Constitutionconstitution.md — immutable project rules
1Visionvision.md — impact model, success metrics
2Strategystrategy.md — research, pillars, risk register
3Tacticstactics.md — codebase audit, action items
4Specsspec.md — MoSCoW acceptance criteria
5Planplan.md, data-model.md, contracts/
6Taskstasks.md — test-first atomic tasks
7ImplementPer-task commits with traceability
8Validateimpact-report.md — drift and impact verification

7 bi-directional gates sit between the phases, running 113 verification checks in total. Each gate also validates four Strategy-and-Tactic assumptions: necessity, achievability, sufficiency and warnings. 7 domain primers load automatically based on the vision.

For regulated and assurance teams

If AI-generated code is entering your audit scope, the artifacts VDD produces are designed to serve as objective evidence.

  • Standards benchmark — VDD assessed against NASA Systems Engineering, CMMI REQM, DO-178C, IEC 62304, DORA, ISO 29148 and GitHub Spec Kit.
  • Compliance evidence templates — produce audit-ready evidence from VDD artifacts.
  • Safety-critical primer — verification patterns for regulated domains.
On the benchmark. The standards assessment is a self-assessment by the author, not an independent audit. Every criterion is published in full so that it can be checked and challenged. Treat it as a stated basis of assessment, not as certification.

Already using Spec Kit? VDD is the upstream half, not a replacement. GitHub Spec Kit is excellent and starts at the spec; VDD works out what the spec should be and verifies nothing was invented on the way to the commit. The spec, plan and tasks chain is reused rather than reinvented.

When not to use VDD

VDD is overhead, and sometimes that overhead is not worth paying.

  • Prototyping or exploring. The chain costs time and tokens you will not recoup on throwaway code.
  • Requirements already clear and stable. Use Spec Kit — lighter, and it solves that problem well.
  • A one-file bugfix. A normal agent session is faster.
  • Role-based team simulation. BMAD-METHOD is the better fit.

Use VDD when you need to prove, later, why a line of code exists.

Get started

# One-line install (detects your agent and wires it up)
curl -sSL https://raw.githubusercontent.com/simonplmak-cloud/vision-driven-design/main/scripts/install.sh | bash

# In your project:
/vdd:init                          # Generate the project constitution
/vdd:vision "your vision here"     # The only human input required

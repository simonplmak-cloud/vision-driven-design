Vision Driven Design

Prove your AI-written code did what the business actually asked for.

AI agents now write most of the code. Pick any function in your repository and ask which business goal authorised it. Most teams cannot answer. VDD gives every commit an audit trail back to the business goal it serves, and flags any code that does not have one.

Why bi-directional

Spec-driven development verifies in one direction: did every specification get implemented? It never asks the opposite question — is there anything here that no specification asked for? Under human authorship that rarely mattered. Agents are different.

Forward verification catches dropped requirements. Backward verification catches invented ones. VDD runs both at every junction, so drift shows up as a failing gate rather than as a subsystem nobody can justify eighteen months later. This is mandatory in aerospace (DO-178C) and medical devices (IEC 62304). AI inverts the arithmetic — the agent maintains the evidence chain as a by-product of doing the work.

Get started

# Install (detects your agent and wires it up)
curl -sSL https://raw.githubusercontent.com/simonplmak-cloud/vision-driven-design/main/scripts/install.sh | bash

# In your project:
/vdd:init                          # Generate the project constitution
/vdd:vision "your vision here"     # The only human input required
